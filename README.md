# EasyGrafana 1.11.4

自动识别 Grafana Explore 的 Chrome / Edge 扩展，提供一键切换的简易 / 高级日志查询模式。

## 安装（三步完成）

无需安装开发工具，也不用执行命令。

1. **下载并解压**：[下载 EasyGrafana](https://github.com/ChangBinHu/easygrafana/archive/refs/heads/main.zip)，将解压后的 `easygrafana-main` 文件夹放到固定位置。
2. **打开扩展管理页**：在地址栏输入 `chrome://extensions`（Edge 用 `edge://extensions`），开启「开发者模式」。
3. **选择文件夹**：点击「加载已解压的扩展程序」，选择 `easygrafana-main` 文件夹，再刷新 Grafana 页面即可使用。

安装后请保留该文件夹。已有旧版时，先禁用旧版，避免重复运行；如浏览器询问网站访问权限，请允许在需要使用的 Grafana 站点运行。

**更新方法**：重新下载并解压，将新文件覆盖到原安装文件夹，在扩展管理页点击 EasyGrafana 的「⟳ 重新加载」，再刷新 Grafana 页面。

## 自动使用

进入任意域名下**已适配的 Grafana Explore 日志页**时，EasyGrafana 自动显示，不需要点扩展图标、不需配置域名，不抢输入焦点。支持子路径，例如 `/grafana/explore`。

普通页面不会显示。站内 SPA 切换时自动跟随。查询栏嵌入原输入框位置，跟随深浅色主题；Alt + Shift + S 聚焦输入框。

可唯一识别的普通查询文本框会被原位替换，输入同步到 Grafana，支持原生 Run Query。复杂编辑器（如 Monaco）或多条相同表达式无法唯一定位时，保留原生框，在查询区上方提供嵌入栏，使用栏内搜索按钮按 URL 执行；找不到查询编辑区域时不显示。

第一次使用 Grafana 仍需在原页面选定数据源和查询范围；插件不会猜测环境或生成任意全量查询。

## 简易模式

```text
request123 ProcessRequest NOT debug
"request failed" NOT "debug mode"
```

支持以下写法：

| 输入 | 含义 |
| --- | --- |
| `request123 NOT debug` | 包含 request123，排除 debug |
| `request123 NOT (11 22)` | 包含 request123，分别排除 11、22 |
| `NOT （11 22）` | 中文括号，同样排除两项 |
| `NOT ("debug mode" timeout)` | 排除短语和单词 |
| `"NOT"` | 检索 NOT 字面内容 |

NOT 不区分大小写；批量排除不支持嵌套，括号必须配对。作为字面内容的括号、NOT 需要放入双引号。

空格分隔多个包含词，AND 关系；`NOT` 表示排除；双引号组合短语。Enter 搜索，空输入清除简易关键词过滤。

自动选择语法：

| 数据源 | `request123 NOT debug` 的过滤条件 |
| --- | --- |
| grep 日志数据源 | `grep request123 \| grep -v debug` |
| Loki | `\|= "request123" != "debug"` |

查询范围、组织、时间、数据源、其他查询和其他面板保留。复杂 Loki 管道会保留并明确提示。Loki 使用字面子串过滤；grep 日志数据源 沿用平台 grep 语义。

## OR 任意匹配

- `11 OR 22`：包含任意一个；支持三个以上词及小写 or。
- `请求ID (11 OR 22) NOT debug`：包含请求ID，并匹配 11 或 22，同时排除 debug。
- `("request failed" OR timeout)`：完整短语和单词也能组合。
- `(11 OR 22) (33 OR 44)`：两个 OR 组都必须满足。
- 支持中文括号 `（11 OR 22）`；输入框内保留括号和 OR 连接词。

与其他条件混用时必须加括号；`请求ID 11 OR 22` 会提示补全分组，不猜测优先级。暂不支持嵌套布尔表达式或 `NOT (11 OR 22)`；排除两项直接写 `NOT (11 22)`。检索 OR 字面内容请写 `"OR"`。

grep 日志数据源 编译为 grep -E，Loki 编译为 |~ 正则过滤；OR 分支自动转义正则特殊字符，按字面内容匹配。生成的 OR 查询可在简易和高级模式间往返。Loki 过滤语法参见 [官方日志查询文档](https://grafana.com/docs/loki/latest/query/log_queries/)。

## 输入框内色块

色块直接显示在简易输入框内，下方不再重复展示。一个检索词一个蓝色色块，NOT 排除词使用橙色；双引号短语整体着色，括号和 OR/NOT 操作符保留原文。

保留原生输入框的光标、选择、复制粘贴和撤销操作。高亮不添加字符或改变空格，长输入横向滚动时同步移动。语法不完整时保留原文并暂停着色，错误提示仍有效。

## 常用检索下拉

简易输入框右侧的 ▾ 可展开常用完整检索条件，输入时按内容过滤。最近使用的优先，使用时间相同时按使用次数降序排列。点击条目或用 ↑ / ↓ 和 Enter 填入，再按 Enter 搜索；Esc 收起。选择条目本身不会执行查询。

提交有效的简易条件时记录，包含插件搜索按钮和已适配的原生 Run Query。次数表示提交次数，不代表服务端返回成功。未提交输入、空输入、无效语法及高级原文不记录。

记录仅保存在当前浏览器的扩展本地存储，按站点和数据源类型隔离；最多保存 100 条（每条不超过 2000 字符），下拉最多显示 12 条。刷新和重启浏览器后保留，不跨设备同步。可在下拉中清空当前站点、当前数据源类型的记录。

## 高级模式

顶部单击「高级模式」只编辑原始检索条件，例如 grep 日志数据源 的 `grep request123 | grep -v debug`，或 Loki 的 `|= "error" | json`。环境选择器不再放入输入框，仍在 Grafana 原位置查看和修改，提交时自动沿用。清空检索条件保留环境范围。无法拆分环境前缀的 Loki 聚合表达式保留完整原文以避免损坏。Enter 换行，Ctrl / Mac ⌘ + Enter 执行。也可点击执行按钮。

两种模式切换会保留未提交内容；无法无损转换的高级查询仍保留在高级模式，显示提示。复杂原查询默认打开高级模式。

展开「查询预览与说明」可选中复制完整语句。多查询时选择要编辑的目标，页面内分别保留草稿。刷新或关闭页面不会保存未提交草稿。

## 兼容边界

- HTTP / HTTPS 任意域名的标准 `/explore` 或子路径 `/.../explore`。
- 旧版 left/right 数组、left/right 对象、新版 panes（schemaVersion 1）。
- 自动识别标准 Loki 数据源和原有 grep 日志数据源 数据源。
- 未适配 Dashboard 内嵌查询、其他数据源（SQL / Elasticsearch / Prometheus 等）、未知状态版本、非标准路由。检测不明确时不会猜测改写。
- 模型类型元数据缺失且无法区分 Loki 与其他数据源时，需要保留原生查询方式；可按需求文档反馈样例以补充适配。
- 不保证任意 Grafana 版本都兼容。已在真实 grep 日志数据源 页面核对普通 textarea 结构；替换、同步、主题及按钮交互在本地模拟页验证。真实扩展重载后的日志结果仍需现场验收。

## 隐私与权限

使用 HTTP/HTTPS 页面 content script 和 storage 权限，不请求 cookies、tabs 或后台网络权限。后台仅负责将常用检索条件和计数写入 chrome.storage.local。扩展不抓取日志、不读凭证、不上传内容；对无关网站仅检查 URL，满足 Explore 路径后才判断页面标识/查询结构。搜索会更新当前 Grafana URL，与原网站一样可能进入浏览器历史。

## 本地开发与验证

本仓库是开发源码的统一维护位置，可克隆到任意本地目录。

开发时直接加载本仓库根目录；保存修改后，在扩展管理页重新加载插件，再刷新 Grafana 页面。原桌面目录不会自动同步更新，更换加载目录可能产生独立的扩展本地存储，旧检索历史不会自动迁移。

分发包通过 `python3 package.py` 生成，输出为 `dist/EasyGrafana.zip`。

在仓库根目录执行（需要 Node.js 和 Python 3）：

```sh
node --test tests/*.test.cjs
node dev-server.cjs
# 打开 http://127.0.0.1:4178/explore
python3 package.py
```

演示页面可切换 grep 日志数据源 / Loki / 新旧 URL / 普通页面，使用同一份运行时代码；不连接真实数据源。

协议参考：[Grafana Explore URL](https://grafana.com/docs/grafana/latest/visualizations/explore/get-started-with-explore/)、[Loki LogQL](https://grafana.com/docs/loki/latest/query/log_queries/)。

## 1.6.2 下拉语法提示

简易模式聚焦输入框、输入文字或点击 ▾ 时，下拉展示常用检索和语法示例。支持包含关键词、双引号短语、NOT 单项排除、NOT (词一 词二) 批量排除、(词一 OR 词二) 任意匹配。

语法项附中文解释，点击会在当前内容末尾追加模板并选中示例词，直接输入即可替换；常用检索项替换整个输入。两种选择都不会自动执行查询。方向键选择、Enter 填入、Esc 关闭；没有选中候选时 Enter 仍执行搜索。没有历史记录也显示语法提示。只提示现有简易语法，不从日志服务获取词典，也不恢复 -debug 写法。

## 1.7.0：选中 JSON 自动弹窗

在已识别的 Grafana Explore 页面中，用鼠标选中完整 JSON 对象或数组，松开鼠标后自动显示格式化弹窗。支持包裹在 JSON 字符串中的对象/数组；保留长数字 ID、数值原始写法和字段顺序。提供复制 JSON、关闭、Esc 关闭；仅在本地处理，不上传或保存所选内容。

普通文本、残缺 JSON、带日志前后缀的整行不会触发，请只选中 JSON 部分。输入框/编辑器内的选择不触发。单次最多 200000 字符、100 层嵌套。页面内 iframe 的选区暂不支持。匹配总数功能仍待服务端统计口径验证，此版本未上线。

## 1.7.1：grep 日志数据源 与通用高级模式

修复 grep 日志数据源 数据源在旧版 Explore 的 expr-only 链接下未识别的问题，域名不设白名单。已适配的 grep 日志数据源和 Loki 支持简易模式。

其它数据源在已支持的 Explore URL 结构中存在字符串 expr 字段时，自动显示高级模式入口，保留原表达式和其它查询字段；不自动套用 grep 或 LogQL，简易模式不可用。无法拆分环境的未知语法显示完整原始表达式。

兼容边界：仍需页面存在可识别的查询编辑区域；不保证所有 Grafana 版本、自定义插件、无 URL 查询状态页面、非 expr 查询字段或仪表盘编辑器均能替换。JSON 选中查看可在已识别的 Explore 页面使用。

## 1.7.2：转义 JSON 片段修复

支持选中没有最外层双引号的转义 JSON 对象或数组，例如 {\"a\":1}；最多解码四层。优先保留已经合法的 JSON，不修改字段内的转义内容，不丢失长数字精度。不补齐残缺 JSON、不删除日志前后缀；选区须覆盖完整对象/数组。

## 1.8.0：复制页面日志

搜索栏旁新增“复制页面日志”按钮。点击复制当前页面 DOM 中已渲染且未隐藏的日志正文，按照页面顺序拼接，保留重复日志和正文换行，不包含图表、查询条件、时间列、标签、行操作按钮或展开字段表格。成功提示实际复制条数；空结果不会覆盖剪贴板。剪贴板 API 失败时尝试浏览器复制后备方式，仍失败则显示错误。

复制范围不是整个时间区间：虚拟滚动未渲染部分、未加载结果和隐藏折叠记录不包含。适配 Grafana logs-row__message 样式及 log-row-message 测试标记；其它定制结构可能无法识别，会提示未找到正文，不回退复制整个网页。单次上限 1000 万字符。

## 1.8.1：多区域日志数据源 简易模式修复

将 多区域日志数据源 数据源名称/类型纳入 grep 日志数据源 语法适配，修复仅含 expr 的多区域环境链接被判定为未知语法、简易模式禁用的问题。简易模式支持包含、NOT、OR；高级模式只展示检索条件。保持原始集群组合、命名空间、timestamp、时间范围和数据源不变。

## 1.9.0：按类型、语法识别，并记忆手动选择

不再只依赖数据源显示名称。自动识别优先使用已声明的 Loki / grep 日志数据源 类型；未声明类型时检查完整表达式中的 grep、LogQL 过滤/解析语法，以及 queryText/value 分离字段；最后才以已知名称辅助识别。明确声明其它类型的数据源不会被自动改解释为日志语法。复杂查询继续保留高级模式。

搜索栏标题旁新增“查询语法”选择器：自动识别、grep 日志数据源、Loki（LogQL）。无法判断时可首次手动选择；手动选择优先于自动识别，按站点 origin、orgId、数据源 UID/类型（旧链接按名称）保存到扩展本地存储。刷新后沿用；选择“自动识别”清除对应记忆。无 UID 的旧链接改名后，模糊空查询仍可能需要重新选择。

切换保留当前草稿、不自动运行查询；同数据源的其它未提交草稿标记需要重新读取，避免套用错误语法。保存失败会说明本次生效但未持久保存。此功能不新增服务端请求或权限，也不等同于适配所有自定义 Grafana 编辑器。

## 1.10.0：一键删除关键词

简易输入框内，每个关键词色块上方显示 × 按钮，点击只删除对应词并同步查询草稿，不自动搜索。短语整体删除；重复词按位置独立删除；NOT 条件删除后不保留悬空操作符；OR 分支删至一个时自动变为普通包含词。删除最后一个词清空检索过滤条件，环境仍保留。按钮可键盘聚焦并带有对应词的可访问名称；语法未完成或不合法时不生成删除按钮。

## 1.10.1：按需显示关键词删除按钮

恢复 34px 单行输入框，删除按钮不再占据单独一行。默认隐藏所有 ×，点击某个关键词色块后，只在该词右上角显示一个 ×，并收起语法下拉菜单。点击其它词切换目标，点击空白/外部、输入或删除后隐藏。删除规则与 1.10.0 一致。


## 1.11.0：选中文字加入搜索

- 在 Grafana Explore 日志中选中文字，旁边显示「＋ 加入搜索」。点击后追加到当前选中的查询，原有关键词、环境和时间范围保留；追加后立即执行搜索。
- 含空格的文字作为一个完整关键词；NOT / OR 当作普通文字，不作为操作符。多查询页面追加到 EasyGrafana 当前选中的查询。
- 简易模式直接追加；高级模式仅在能无损转换时追加并保持高级模式，否则提示原因并保留原文。无效草稿或不支持的字符不会覆盖现有查询。
- 完整 JSON 仍优先自动打开 JSON 查看弹窗；编辑框内选字不触发。仅支持单行、最多 2000 字符，去掉首尾空白。
- 点击空白、Esc 或取消选区收起按钮；滚动时跟随选区，移出屏幕后收起。插件更新后请重新加载扩展并刷新 Grafana 页面。
